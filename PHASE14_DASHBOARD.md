# PHASE 14: MARL SUPPLY CHAIN RESEARCH DASHBOARD

## Overview
Phase 14 implements a visualization and analysis interface built on **Streamlit** and **Plotly**. The dashboard is strictly read-only and explicitly designed to surface verifiable data artifacts generated during Phases 6–13 without fabrication or in-memory spoofing.

## Architecture & Data Flow
The dashboard relies on a separation of concerns between the data ingestion layer and the UI visualization layer.

1. **`dashboard/data_loader.py` (Ingestion Layer):**
   - **`load_registry()`**: Lazily parses `models/registry.json`. Handles gracefully missing registry files.
   - **`load_evaluations()`**: Sweeps the `results/phase7` directory, extracting JSON outputs generated by `rl/phase7_evaluator.py`. It converts over 960+ historical trajectory metrics into an indexed Pandas DataFrame.
   - **`load_statistical_analysis()`**: Imports the `PHASE8_STATISTICAL_ANALYSIS.md` artifact representing authoritative FDR-adjusted metrics.
   - **Missing Data Handling:** If an experimental run lacks evaluation data (e.g., failed to finish training), it is correctly surfaced as a missing block instead of throwing an unhandled exception or fabricating zeroes.

2. **`dashboard/app.py` (Visualization Layer):**
   - Renders a multi-page interactive web interface containing:
     - **Overview:** Summarizes artifact volumes and their implementation/execution statuses.
     - **Model Registry:** Provides a searchable table containing validation hashes.
     - **Experiment Explorer:** Tabular inspection of evaluation metrics (costs, fill rates, bullwhip effects) filterable by algorithm, scenario, and seed.
     - **Model Comparison:** Boxplots distributing the target metrics per algorithm.
     - **Scenario Analysis:** Bar charts identifying model resilience across distinct simulation regimes (e.g., `demand_shift`, `capacity_disruption`).
     - **Live Simulation Replay:** Enables interactive time-series plots of agent inventory states and ordering actions over a sampled trajectory. (Uses a trajectory mocking hook to demonstrate architecture until full trajectory artifacts are actively serialized).
     - **Statistical Results:** Integrates the markdown summary proving FDR significance.
     - **Reproducibility:** Displays hardware metrics and cross-references CLI utilities to cryptographically check loaded artifacts.

## How to Run
Ensure `streamlit` and `plotly` are installed. Start the server using the designated virtual environment:
```bash
.\.venv\Scripts\python.exe -m streamlit run dashboard/app.py
```
This will spin up a local instance accessible via browser at `localhost:8501`.

## Testing
- **Suite location:** `tests/test_phase14_dashboard.py` and `tests/test_phase14_app.py`.
- **Coverage:** Data loading resiliency, JSON parsing resilience against malformed schema structures, relative path import stability.
- **Execution:** Run natively using standard PyTest. A mocked Streamlit context session (`AppTest`) explicitly verifies that UI components initialize without rendering errors.

## Limitations & Missing Data Behavior
- The visualization explicitly restricts claims of statistical superiority to the Phase 8 outputs. Minor graphical discrepancies in the "Model Comparison" graphs are heavily footnoted warning against visual pseudoreplication.
- If a checkpoint is identified as `CORRUPT` by the registry, the dashboard logs this status in the Registry page but allows viewing of any valid historical evaluation artifacts tied to it (since the artifacts were technically gathered prior to corruption).
